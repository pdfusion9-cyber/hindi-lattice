## Training gate: intentionally closed

The training workflows fail closed unless every text source used by the expert manifest has:
- immutable dataset revision and exact split/config;
- license identifier and official terms URL;
- documented commercial-training permission and public redistribution permission (Release assets are public);
- reviewer and review date;
- completed PII, consent, schema, split, and text-model compatibility reviews.

No dataset is approved in the supplied package. Do not change this status by inference from a dataset name or a generic license badge. A human rights/provenance review is required.

## Data-to-expert compatibility findings

The current `prepare_expert_corpus.py` extracts a fixed set of common text fields and ignores binary image/audio payloads. Its current schema therefore does not yet implement the intended modality paths:

| Expert | Candidate source(s) | Current blocker |
|---|---|---|
| 3 Reading & Q&A | DocumentVQA | Image/page payload and OCR/visual grounding path is not implemented by the text-only extractor. |
| 4 Read-aloud / TTS | IndicVoices-R, LibriTTS | Audio decoding, speech targets, voice/consent audit, TTS model and vocoder are absent; text transcript alone is not TTS training. |
| 9 Tables & ledgers | PubTabNet | Image/table structure and cell-coordinate supervision need a dedicated table/OCR parser; generic text flattening loses structure. |
| 10 OCR & PDF layout | olmOCR mix | Page images/layout supervision need a vision encoder and layout-aware sidecar; binary image payload is skipped. |
| 17 Coconut planning | gov_report_qs | Nested `document_sections` and `question_summary_pairs` need explicit schema mapping and task-preserving serialization. |
| 19 Fabric Swarm tools | Glaive function calling | Nested `conversations` and `tools` structures need a parser that preserves role, tool schema, arguments, and call/result boundaries. |

Additional review required for every dataset: confirm the live repository exists, pin a commit revision, inspect actual configs/splits/schema and license files, inspect source provenance/third-party rights, and run PII/consent checks. The supplied dataset IDs are candidates, not grants of rights.

## Blueprint implementation gaps (not production-complete)

The package traceability matrix correctly marks these as pending or reference-only:
- Native packed W1.58A8 ternary weights, quantization calibration/parity, and mobile kernels.
- Production fused Gated-DeltaNet/Mamba implementation.
- SnapKV/KIVI integration into the actual attention KV-cache path; current utilities are reference helpers.
- Explicit 128 meta-token bank.
- Full Titans fast weights, 48–64 MB budget, SWR sleep scheduler, and DoRA consolidation.
- GateSkip/LayerSkip and speculative decoding integrated and quality-calibrated.
- AiSAQ, HPC-ColPali, M+, PEER, full document vector store/retrieval.
- Production Coconut latent planning, Huginn 4–32 depth, trained SCoRe/MNL policies.
- Real OCR/vision and TTS/audio sidecar weights.
- Android ExecuTorch/vendor-NPU and iOS Core ML exports; offline device tests, sustained thermals and battery benchmarks.

The 580 MB target is not achieved: 1.58-bit arithmetic alone is estimated at 607.29 MB before scales, metadata, tokenizer, routing tables, alignment and runtime. The blueprint's 0.68–0.75 GB range is a more realistic initial measurement target, still unverified.

## Public runner and continuous-loop cautions

- The workflow requests 20 parallel public `ubuntu-24.04` jobs. Public-runner preflight does not guarantee that GitHub will schedule all 20 simultaneously on every account or that the full CPU training workload will fit the advertised VM memory.
- Each expert job is configured for a bounded 280-minute session and saves a resumable shard every 250 steps and at session end, including optimizer state. This logic is present in source; it has not yet been exercised by a full-size training cycle.
- The shared-base phase is separate and must finish before expert shards can train against one immutable base.
- Merge is designed to preserve the exact tensor set/shapes and parameter count. Synthetic tests are not evidence of successful real checkpoint merge after training.
- Do not describe this loop as continuously running until GitHub Actions run history and persisted checkpoint assets confirm each stage.

## Required next gates (in order)

1. Complete rights/provenance review and exact revision/config/split pinning for approved text datasets; keep audio/vision/table datasets on separate sidecar tracks until their modality pipelines exist.
2. Add dataset-specific schema adapters and tests; preserve instruction/response roles, nested tool calls, table cells and document hierarchy.
3. Run bounded corpus preparation on public runners; verify nonempty train/validation files, sample records, hashes, leakage checks and per-expert counts.
4. Run a bounded shared-base training dry run with memory/time telemetry and checkpoint/resume verification.
5. Run one bounded expert shard end-to-end; verify optimizer resume and immutable base/config/tokenizer fingerprints.
6. Only then dispatch the 20-way expert matrix; merge with exact key/shape/parameter-count checks and evaluate all experts.
7. Implement quantization, mobile exports and offline device acceptance tests before claiming a phone-ready offline model.
